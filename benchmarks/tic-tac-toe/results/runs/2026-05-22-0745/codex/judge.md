## Observations

- Win highlight goes well beyond a background-color swap: a positioned `::after` on the board element draws a yellow pencil-style line whose orientation is selected via a `data-win-line="a-b-c"` attribute matched to per-line CSS rules (row → horizontal, column → 90° rotated, diagonals → ±45° rotated). The probe only measured background-color contrast and missed this detail entirely.
- Logic / DOM separation is enforced by two distinct `<script>` blocks within one HTML file: the first publishes `TicTacToeLogic` to `globalThis`, the second consumes it for DOM wiring. The test file grabs the logic block by its `id` attribute (`<script id="tic-tac-toe-logic">`) — a more robust extraction than matching the first script element.
- Score normalization is uncommonly thorough: `normalizeScore` requires `Number.isFinite(value) && value >= 0` and then applies `Math.trunc` before accepting any persisted number. Floats, negatives, NaN, strings, and null all degrade to 0.
- Accessibility done quietly and correctly: `aria-live="polite"` on status, `aria-label` on each cell that updates as the mark changes ("Square 1, empty" → "Square 1, X"), labeled score region, `focus-visible` styles, viewport meta tag.
- Shipped `AGENTS.md` containing only a stray `<claude-mem-context>` block from a different agent's system prompt. Harmless but indicates the output directory was not cleaned before handoff.
- "Reset Scores" updates `scores` but does not call `renderBoard` or clear `isGameOver`. If the user finishes a game and then clicks "Reset Scores" without first hitting "Restart", the scoreboard zeros but the board stays frozen with the previous outcome and the strike-through line. Defensible by design (the buttons are distinct concerns) but mildly surprising.
