## Observations

- Static HTML board markup: cells are written out in the source rather than generated by JS at runtime, so the grid is in the DOM before any script executes. This both speeds first paint and makes the file readable end-to-end without mentally simulating a build step.
- Win line is visualized with a real overlay stroke (`.win-stroke[data-line=...]`) positioned via per-line CSS for all 8 lines, including rotated translates for the two diagonals. More work than a background-color tint and produces a tic-tac-toe-authentic "struck through" feel.
- Logic is exposed on `window.TicTacToeLogic` and the test file extracts it from the HTML via regex + `vm.runInContext`, so there is no duplicated source to drift between — a different (and slightly tidier) solution to the same single-file constraint that the claude run handled with a sibling `.logic.js`.
- `recordResult` is explicitly tested for input-immutability (asserts the original `initial` object is unchanged after the call) — uncommon and a good sign of intentional functional discipline.
- Accessibility: aria-live status, role="grid"/"gridcell", focus-visible outlines, and dynamic aria-labels per cell. Minor smell — the empty-cell aria-label includes `"X's turn"` on every cell, so AT users will hear the current-player phrase nine times across the grid, which is noisy.
- Documentation has a small gap: the win-stroke CSS is the most non-obvious piece of the file (per-line transforms, 118% width on the diagonals for visual reach) and has zero comments explaining it.
