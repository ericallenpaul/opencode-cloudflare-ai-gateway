## Observations

- **The headings bug is the most interesting finding in this entire benchmark run series.** Unit tests pass with flying colors (30+ assertions, including XSS edge cases other runs miss), but the parser ships a real correctness regression that the test suite never exercises: typing six consecutive headings without blank lines between them produces a paragraph instead of six `<h*>` tags. The fix is one line — either split each block on `\n` and dispatch per-line (preferred), or relax `m[0] === b` to scan within multi-line blocks. The lesson is "unit tests don't equal coverage" — the test suite focused hard on adversarial inputs but missed the trivially-realistic happy-path case of stacked headings.
- **Best XSS test breadth in the benchmark so far**: null-byte smuggling, direct sentinel-marker injection (`\x01C0\x02`), image-syntax with dangerous URLs (`![x](javascript:...)`), case-insensitive scheme matching. The control-char strip upfront elegantly prevents the sentinel-injection class entirely — confirmed by a passing test.
- **Subtle correctness detail**: the blockquote detector matches `^&gt; ` (entity form) because the whole input is HTML-escaped before block scanning. Same care as the 1236 run, different bug context.
- **Bare-bones UX compared to other claude runs**: no header bar, no dark theme, no sample seed text in the textarea (just a placeholder). The styling is technically correct but visually less polished than the 1236 run (header bar + tinted blockquote + styled `<pre>`).
- **Mobile layout doesn't stack**: `.app { display: flex; height: 100vh }` with no media query. `mobile.png` shows both panes cramped at ~150px each. Same gap as the 1522 and 1236 runs.
- **`docs/superpowers/plans/2026-05-26-markdown-editor.md` leaks framework internals into the deliverable.** Persistent low-severity gripe across the benchmark.
