## Observations

- **Strong defensive posture**: scheme allowlist (http/https/mailto/tel) over blocklist, control-char + whitespace stripping before scheme check, `rel="noopener noreferrer nofollow"` on every anchor, `escapeAttr` adds backtick-escaping on top of HTML escaping, render path wrapped in try/catch with a `textContent` fallback. This is the most security-conscious parser in this comparison.
- **Two-pass placeholder design is well-executed**: code spans and links are replaced with `<n>` placeholders *before* emphasis is processed, so `**a** inside [link text](url)` and `` `**a**` `` literal can't collide. Cleaner than the regex-ordering approach.
- **Invalid links degrade gracefully**: rejected `javascript:`/`data:` URLs become visible `<span class="invalid-link">text (raw-url)</span>` rather than silently disappearing — the user can *see* that something was rejected, which is friendlier than a vanished link.
- **Documentation is the standout failure**: `README.md` is one line, the planning doc under `docs/superpowers/plans/` is also one line. The spec explicitly scores documentation as a quality dimension and this run shipped empty stubs. Also leaks a framework-internal artifact (`docs/superpowers/`) into the deliverable, which a user-facing run probably shouldn't expose.
- **Mobile layout doesn't stack**: CSS uses `.app { display:flex }` with `.pane { flex: 1 1 50% }` and no media query. `mobile.png` confirms the two columns stay side-by-side at narrow viewport, causing right-pane content to truncate. Should be `flex-direction: column` below ~600px.
- **Minor seed quirk**: the seed string ends with `.replace(/`/g,'`')` — a no-op that replaces backticks with themselves, likely a leftover from earlier escape attempts. Harmless but suggests the seeding code was edited under time pressure.
