## Observations

- **Critical drift bug caught by visual inspection that the functional tests missed**: the parser exists in two places — `markdown.js` (used by tests) and an inline copy in `markdown.html` (used by the browser). The inline copy uses `'\\n'` (literal backslash-n string) in three places where it should be `'\n'` (newline character). Result: the browser renders `<pre><code>` and `<blockquote>` content with visible `\n` text where newlines should be. `empty.png` proves it. The functional R6/R8 only check that the right *elements* exist, not that the text content is correct, so they pass.
- **Single-source-of-truth violation**: the comment `// --- Parser (mirrors markdown.js; no external dependencies) ---` explicitly acknowledges the duplication and the intent that the two stay in sync. They don't. claude's run handles this better by extracting the parser from the HTML at test time via `vm.runInContext`, eliminating any drift possibility.
- **Dark theme is the only run with this design choice** — pane header bars (`Markdown` / `Preview`), `#1e1f22` chrome, `#5fb3ff` link color. Visually distinctive. Would be more polished if mobile layout stacked.
- **README is an empty stub** — identical pattern to the opencode 0758 run. Spec explicitly scores documentation, this drops 5 points.
- **URL allowlist is the strictest in the comparison** — only `http://` and `https://` pass; `mailto:`, `#fragments`, relative paths, root-relative paths all get dropped to text. Defensively excellent for adversarial content, but may surprise users who expect mailto links to work.
- **`docs/superpowers/plans/...` leaks framework internals into the deliverable** — same artifact-leak issue as in earlier runs.
